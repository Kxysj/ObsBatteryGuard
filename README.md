# OBS 电池安全录制 v1.0.17

面向 Windows 笔记本无人值守场景的 OBS 录制保护助手：支持低电量自动停录、定时分段、延时关机与可读日志，降低电池耗尽导致的录像损坏和数据丢失风险。

本工具通过 OBS 28 及以上版本内置的 WebSocket 控制录像，尝试在电池耗尽前停止、确认并等待文件写入，再根据配置关闭 Windows 或休眠。MKV 与等待写入都不是零丢失保证。

使用前，请在有人值守的情况下完成测试，合理设置电量阈值、分段及关机参数，并做好重要数据备份。关机或休眠功能可能影响其他正在运行的程序，请确认相关设置。重要录制场景不应将本软件作为唯一保障。

- 保留 v1.0.15 的进程绑定：隐藏窗口不结束界面进程；真正退出或界面进程异常结束才会一并结束所属守护，不留下本软件的后台自动任务。

### v1.0.15 关闭后后台不再独立运行

- 修复确认的生命周期缺口：旧版后台通过独立进程启动，界面崩溃、被任务管理器结束或绕过正常关闭流程时，守护可能继续分割/保护；多个界面也会共享同一个守护，造成“关闭的是哪个实例”不清楚。正常关闭原来已有退出协议，但不能覆盖这些异常退出路径。
- 新版使用 Windows Job Object，将守护先以挂起状态创建、绑定到界面，再恢复执行；绑定失败即取消启动，不运行不受管理的新后台。界面进程结束时，Windows 自动结束它所属的守护，不依赖界面还能发送退出消息。正常退出仍优先取消任务、写日志、等待守护结束；强制结束无法保证最后一条日志落盘。
- OBS 和其他由守护启动的独立应用不加入此容器，不会因退出本软件被连带结束。退出不自动停止 OBS 录像，不改变 OBS 自己的输出设置；已经送达 OBS 的一次操作以及已提交 Windows 的电源动作不能保证撤回。
- 新版主界面单实例；发现仍开的旧版界面时提示先退出，不再打开另一套界面共享后台。发现遗留守护时核验会话/PID/启动时间/路径/产品身份并接管其生命周期；接管失败明确报错、禁用正常控制入口，不将它当成已绑定的正常守护。
- 新版正式守护必须携带有效界面进程身份（PID、启动时间、同目录界面路径），缺失/不匹配立即退出；旧式仅启动 `--background` 的启动项不会使新版守护孤立常驻。守护另有所属界面退出监视。隔离测试模式不连接真实 OBS；预检模式只作只读查询，两者均不是常驻运行入口。
- 检测与工具的只读预检增加 OBS 自带分割配置检查。软件的自动分割是定时发送 `SplitRecordFile` 或停止/重启命令，不写入 OBS 的 `RecSplitFile*` 配置。OBS 自带分割如果独立启用，关闭本软件后仍能分割；不能把这种现象一律认作后台残留，也不擅自改掉用户的 OBS 设置。
- 本次当前电脑没有运行中的界面/守护/OBS，最新可读生产日志为 9 月 11 日且记录正常退出，未取得用户本次分割发生时的现场日志，不能断言这一次分割一定由残留进程导致。上述代码缺口已修复，真实现场仍需升级后复核。
- 验证结果：原有 50 项回归通过；新增 6 组进程绑定/只读分割诊断回归通过（含真实隔离进程强制结束、分割调用不再增加、独立 OBS 替身存活、旧进程接管与孤立启动拒绝）；发布版实际界面 EXE 的所属身份与正常退出测试通过；发布版守护退出日志、离线 UI 及托盘测试通过。没有对实际 OBS 录制、实际关机或个人启动项执行修改。

### v1.0.13 统一退出界面与后台

### v1.0.12 连接体验与字号

- 点击“连接 OBS”时检查本机 OBS 是否运行：未运行且未启用自动启动时询问是否打开；选择否不启动也不发送连接命令；已启用“OBS 未运行时自动启动”则直接打开。已运行时直接连接，不重复打开。
- 一次性确认不会修改自动启动配置；启动由后台守护统一处理，查找已保存路径和常见安装位置，并在启动后最多等待 30 秒建立连接。路径错误、启动失败或 WebSocket 未就绪都有明确提示；30 秒内不重复拉起进程。非本机连接地址不会启动本机 OBS。
- 连接按钮使用已经保存的参数，修改路径/端口/密码后仍需“保存全部设置”。如果启用了“连接 OBS 后自动录像”，连接成功仍会遵从该设置，启动确认会提醒这一点。
- 修复密码框重复内边距和固定内容区导致的遮罩字符裁切；正文/按钮使用 14，文本框/密码框/下拉框 15，参数辅助说明 13（WPF 逻辑字号）。输入控件使用至少 42 的高度，随字号扩展；较长标签自动换行。
- 编译通过；35 项模拟回归通过（含新增 6 项启动流程场景：确认启动、自动启动、已经运行、不允许启动、启动失败、非本机地址）。确认/取消分支、四种尺寸 60 张页面渲染、15/18/22 三种字号的密码框内容区及另外 3 张渲染通过。未启动实际 OBS 或执行真实录制/电源操作，多 DPI 原生窗口效果仍需目标电脑确认。
- 本次连接启动流程需要同目录的 v1.0.12 主界面和守护配套使用；不自动替换正在运行的旧守护。请在停录并取消电源计划后按下文切换。

- 日志页后台增量读取，单次最多 256 KiB、保留最近 1200 行；支持暂停、事件搜索、警告/错误筛选和完整当前日志快照导出。跨午夜自动换文件，不自动删除历史日志，请定期归档。
- 状态错误、更新时间和忙碌按钮更清晰，录像时长支持超过 24 小时；增加最大化按钮，小窗口状态卡片两列显示，修正页面标题与按钮重叠、日志垂直居中。
- 已增加模拟 OBS WebSocket、参数热更新、坏配置、日志截短/半行/跨日测试，以及四页面两种尺寸的离线渲染和部分控件断言。仍需在实际笔记本、实际 OBS 和系统 DPI 下有人值守验收；没有执行真实关机、断电测试。

### v1.0.8 安全核心（保留）

- 电池监测独立于 OBS 查询和分割；手动停止、低电量停止会抢占并取消分割。
- 断连、查询失败不再视为已停止。未确认停止时阻止普通关机，紧急兜底策略仍保留。
- 日志初始化、写入及订阅者故障不再抛出到保护流程；故障时保留最多 200 条内存日志并在界面告警。内存日志不能抵御断电。
- 本机通信增加并发监听和请求读取超时。界面不再强杀或自动替换已有守护程序。
- 关机/休眠倒计时由守护程序持有；紧急计划可缩短普通计划，提交 Windows 后不再误报可取消。非强制关机可能被其他应用阻止。
- 已通过编译、原有冒烟测试和模拟故障回归。没有进行实际断电、实际关机或多 DPI 窗口验收。
- 后续第三阶段重点是实际 OBS/电池/电源策略联调与有人值守故障验收；托盘管理、日志保留策略和更深入的视觉优化尚未纳入本轮。

### 从旧版切换

升级前先按旧版的退出流程结束旧操作界面和后台，再打开新版。v1.0.16 的 × 仅收起窗口，需要退出请右键托盘图标选择“退出软件…”。若后台版本不一致，按此流程退出后重新打开新版，即可使用同目录的配套守护；旧后台不支持正常退出时会再询问强制结束。不想中断录像保护时先取消退出，待完成录像后再切换。

退出整个软件会取消尚未提交的电源倒计时并停止保护，OBS 本身继续运行。已提交的系统动作不能保证撤回，其他软件的关机计划不由本版管理。

## 快速开始

1. 保持 `OBS电池安全录制.exe` 和 `ObsBatteryGuard.Guard.exe` 在同一目录。
2. 打开 OBS，进入“工具 → WebSocket 服务器设置”。
3. 启用 WebSocket 服务器，确认端口（默认 4455），设置密码。
4. 运行 `OBS电池安全录制.exe`，在“参数设置”中填写端口和密码并保存。
5. 若当前不是 MKV：停止录像并退出 OBS，在“检测与工具”中点击“一键设置 MKV”；也可在 OBS 中手动设置。
6. 重新启动 OBS，点击“运行只读预检”及“运行配置与连接检查”。
7. 先接通电源执行“安全停止演练”。演练会停止录像，本身不安排关机；真实低电量保护仍有效。
8. 自检只是配置检查。先用不重要的录像完成本机有人值守验证，再考虑无人值守使用。
9. 点击 × 收起到右下角托盘，保护继续运行；右键托盘选择“退出软件…”并确认，才会结束界面和后台全部功能。

## 工作方式

- 主界面负责操作和参数设置。
- 右下角托盘图标反映当前状态；× 收起到托盘，单击图标恢复界面，右键菜单可确认退出软件。
- 独立的 `ObsBatteryGuard.Guard.exe` 是监控工作进程。收起/最小化窗口时继续运行；从托盘确认退出时一并关闭它。
- 守护与界面进程绑定；新版不允许单独启动隐藏守护。界面异常结束时，所属守护也由 Windows 结束；OBS 保持独立运行。
- 勾选“软件随 Windows 启动”后，主界面将完整软件写入当前用户开机启动项，不需要管理员权限，不单独注册隐藏守护。
- 主界面与守护进程只通过 Windows 本机命名管道通信。
- 启动新版主界面时保留已运行的守护程序，不根据响应超时自动结束进程。
- OBS 只连接设置的 WebSocket 地址，默认是 `127.0.0.1`。
- OBS 密码通过 Windows DPAPI 按当前用户加密保存。

## 自动分割

软件优先调用 OBS 的原生 `SplitRecordFile` 功能。若当前 OBS/输出配置未启用原生文件分割，并且启用了兼容模式，软件会等待 OBS 确认旧文件完全停止，再等待设定的毫秒数，然后在可调超时时间内持续尝试开始新文件并确认录像状态。兼容模式会产生短暂录像间隔，日志中会记录停止确认、重启次数和最终结果。

## 低电量流程

达到停止阈值后，软件依次执行：

1. 取消分割或启动操作，记录“开始安全停止”；日志异常不阻止后续操作。
2. 向 OBS 发送停止录像指令。
3. 轮询确认 OBS 已停止，最长等待设定的超时时间。
4. 再等待设定的文件落盘时间。
5. 按配置安排关机或休眠。
6. 如果倒计时期间接通电源，可自动取消关机。
7. 达到紧急阈值时，紧急关机策略优先于正常倒计时。

## 配置和日志位置

- 配置：`%LOCALAPPDATA%\ObsBatteryGuard\settings.json`
- 易读中文日志：`%LOCALAPPDATA%\ObsBatteryGuard\logs\guard-日期.log`
- 结构化诊断日志：`%LOCALAPPDATA%\ObsBatteryGuard\logs\guard-日期.jsonl`
- 异常标记：`%LOCALAPPDATA%\ObsBatteryGuard\guardian.running`

`.log` 是供用户直接阅读的完整中文日志，`.jsonl` 是供程序诊断的结构化副本。开始/停止、低电量、OBS 响应和关机等关键事件会同时写入两份日志，并使用写穿透主动刷新到磁盘。两份文件都允许在守护进程写入期间安全读取。程序下次启动发现异常标记时，会提醒检查最后一个录像分段。

## MKV 一键设置说明

一键设置会修改当前 OBS 配置文件中的简单输出和高级输出格式。它只在 OBS 已完全退出时执行，并先生成带时间戳的 `basic.ini.backup-*` 备份。如果使用便携版 OBS 或自定义配置目录，软件可能无法自动定位；此时请在 OBS 中手动选择 MKV，或者关闭“强制 MKV 检查”。

## 退出整个软件

右键任务栏右下角的盾牌托盘图标，选择“退出软件…”并确认。正常情况下界面和后台一起退出；旧后台或退出超时会要求二次强制结束确认，未成功则保留界面告知。退出不自动保存/停止 OBS 录像，也不关闭 OBS。点击窗口 × 或 Alt+F4 仅收起到托盘，保护继续运行；托盘不可用时会保留窗口，并通过 × 提供退出确认。

无需为本次退出取消开机启动；如果以后也不希望随 Windows 启动，请在“参数设置 → 启动与日志”取消“软件随 Windows 启动”并保存。

## 退出后 OBS 还在分割？

先在任务管理器“详细信息”确认 `OBS电池安全录制.exe` 和 `ObsBatteryGuard.Guard.exe` 是否仍在运行，以及实际程序路径/版本。需要真正退出时请右键托盘选择退出，不能只点 ×、最小化或取消确认。首次升级请退出全部旧版实例，再打开 v1.0.16。

若这两个进程都不存在，本软件无法继续发送定时分割命令。请核对 OBS“设置 → 输出 → 录像 → 自动文件分割”、OBS 脚本/插件和其他控制工具；本软件不自动修改这些配置。“检测与工具 → 运行只读预检”可查看磁盘中的 OBS 分割开关、类型、时间/大小；OBS 运行时尚未保存的设置仍应以其界面为准。

开发隔离验收：`dotnet run --project tests/ObsBatteryGuard.Smoke/ObsBatteryGuard.Smoke.csproj -c Release -- --test-ownership "发布目录/ObsBatteryGuard.Guard.exe"` 验证正常释放、强制结束、旧进程接管、孤立启动拒绝及模拟分割停止，使用临时配置与进程替身，不控制真实 OBS/电源。发布版主程序 `--owner-check "隔离输出目录"` 验证实际界面 EXE 身份、进程绑定及正常退出；不加载个人配置或启动项。

## 右下角没有直接看到图标？

先点通知区域的 `^`（显示隐藏的图标），查找本软件的盾牌图标。Windows 可能将新图标自动收进此处；软件不能保证强制钉在可见区域，也不会擅自修改系统图标隐藏策略。

- Windows 11：右键任务栏 → 任务栏设置 → 其他系统托盘图标（有的版本名为“任务栏角溢出”），开启“OBS 电池安全录制”；也可在支持的系统上从 `^` 弹出区拖到可见区域。
- Windows 10：任务栏设置 → 通知区域 → 选择哪些图标显示在任务栏上，开启本软件。
- 若 EXE/任务栏仍显示旧图标，请取消固定的旧快捷方式，从新版目录启动后重新固定；不要直接删除 Windows 图标缓存或重启正在工作的资源管理器。
- 若仍运行旧版隐藏守护，仅升级文件不会让旧进程自动获得托盘。请按“从旧版切换”退出旧实例并打开新版主界面；新版正常启动会沿用已有的开机启动偏好并更新程序路径。

## 可靠性边界

本软件用于解决健康电池正常逐步耗尽时的录像保存问题。电池物理故障导致的瞬间断电、SSD/文件系统故障、Windows 内核死机或硬件损坏无法由单一软件绝对保证。关键场景应同时使用 USB-C PD 后备供电、UPS 或第二台设备冗余录制。

不要把停止阈值设置得过低。老化电池可能从较低电量突然跳到 0%，建议实际测试后保留至少两倍于“停止 OBS + 文件落盘 + 关机”所需的电量。
